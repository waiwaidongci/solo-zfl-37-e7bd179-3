# 墨锭试磨室 · 配方任务中心

为墨坊试验员管理的试磨任务中心：墨锭按 **待配样 → 排队试磨 → 试磨中 → 待复评 → 已归档** 流转（另可取消），每一步都校验角色与前置条件，所有操作留痕时间线。

## 运行

```bash
npm start          # http://localhost:3037
npm run verify     # 端到端自动验证（独立端口与临时数据文件，不影响正式数据）
```

数据保存在 `data/ink-stick-testing.json`（原子写入，重启不丢）。首次启动若无数据文件，会生成覆盖各状态的演示数据；旧版档案格式会自动迁移。

## 角色

| 身份 | 角色 | 权限 |
| --- | --- | --- |
| 王守墨 | 管理员 | 全部操作 + 指定试磨人 + 退回任意环节 + 取消任务 |
| 李研 / 陈砚 | 试验员 | 建档、配样、开始试磨（成为试磨人）、记录试磨组、提交复评 |
| 赵鉴 | 复评员 | 复评通过 / 退回待复评任务 |

页面右上角切换身份。**复评人不能是试磨人**；退回、取消必须填写原因；越权、跳步、缺样本编号、记录不完整都会被拒绝并写明原因，且被拒尝试也会记入时间线。

## 规则要点

- 同一墨锭可建多组试磨，每组独立记录配方、纸样、温湿度、样本编号、阶段意见与评分
- 「配样完成」要求每组都有样本编号；「提交复评」要求每组五项记录 + 阶段意见齐全
- 任务支持截止日期：逾期与 3 天内到期会在页面顶部异常条提醒；试磨中数据不完整也会提醒
- 重复/并发请求只生效一次：变更接口支持 `Idempotency-Key` 幂等重放，服务端互斥锁保证并发流转唯一生效
- 全部操作（含被拒绝的尝试）写入任务时间线，可追溯操作人、时间、状态变化与原因

## 接口一览

```
GET    /api/tasks?status=&q=&overdue=&mine=   任务列表（筛选）
POST   /api/tasks                             创建任务
GET    /api/tasks/:id                         任务详情（含可用操作、时间线）
POST   /api/tasks/:id/groups                  新增试磨组
PATCH  /api/tasks/:id/groups/:gid             记录/修改试磨组、追加阶段意见
POST   /api/tasks/:id/transition              流转：sample_ready / start_grinding /
                                              submit_review / approve / return / cancel
GET    /api/stats                             状态统计与逾期数
GET    /api/alerts                            逾期 / 临期 / 数据不完整提醒
GET    /api/users                             身份列表
```

变更请求需带头 `X-User-Id`（身份）与 `Idempotency-Key`（幂等键，前端自动生成）。
